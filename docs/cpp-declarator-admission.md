# C/C++ 声明符准入与限定名修复

2026-09-27。基线为 `88a5b2f`（提取实现与 `545a958` 相同），生产提取版本由 24 升至 25。

## 本轮生产修复

1. **类型位置不再生成字段。** `Word value;` 只提取 `value`，即使全项目其他文件存在名为 `Word` 的宏。独立成员宏由已有声明宏恢复流程提取实际生成的字段／方法，不再添加宏名占位字段。宏定义节点仍保留。
2. **统一损坏 AST 中的函数准入。** 拒绝嵌套宏实参被误解成函数、前一空宏被当成返回类型等形态；排除预处理指令模板本体和控制关键字伪节点。保留合法同名声明、构造函数、函数指针和 GNU 嵌套函数。
3. **补全类外方法的命名空间。** AST 提取和文本恢复使用同一限定规则，处理相对、部分限定和显式全局接收类型，防止修正限定名后文本恢复再插入一份旧限定名节点。变量声明中的普通空白不再被误当成 `::`。
4. **拒绝错误包装节点时继续访问其函数体。** 错误 AST 可能把后续真实类型吞进去；只丢弃包装节点会连带丢失真实类型。OceanBase 中的 `ObjHashCalculator` 模板特化是本轮全量差异检出的保留对照。

类型位置伪字段源于 `7f81a455` 的宏成员补救分支：只要 `type_identifier` 命中全项目宏名集合就生成字段，没有要求它占据声明符位置。其余多数问题在上一轮修复前的 `bfe0a38` 已可复现。方法限定名问题来自 `extractMethod` 直接用 `receiverType::name` 覆盖当前命名空间；本轮同时修正其文本恢复入口。

这些规则没有使用 OceanBase/MAME 路径或特定宏名称作为过滤条件。

## 正向保留与边界

新增中性测试覆盖真实类型字段、同名宏与真实字段／函数共存、函数指针、对象宏生成的字段／方法、模板方法、相对／部分／全局限定名，以及损坏 AST 下的恢复去重。

`Result (invoke(int));` 本身是合法声明，所以不能仅凭括号形态删除。新规则只排除带解析错误的完整括号声明符恢复形态；`Result (invoke)(int);` 同样保留。

本轮撤回了一项实验性扩大过滤：把所有宏同名变量都要求具有 AST 中的原始分号。它虽然能删除 `PORT_COCKTAIL` 等语句宏伪变量，却也会删除 `inflateCodesUsed` 这类参数宏原型的现存名称节点。它原先被错分为变量，但直接删除仍会损失 API 覆盖。因此这部分需在能够恢复真实函数后再处理。

仍未解决的类别包括：部分后置属性宏、`OF/JPP` 参数列表包装宏、复杂语句宏边界，以及不完整展开残片。此次没有把这些节点统一按名称删除。

## 存量索引和 sync

版本 25 会使版本 24 的提取结果过期，完整重建后才能消除未修改文件中的旧伪节点和旧限定名。普通 sync 不会自动修复所有未修改文件。

命名空间变更的正反向 sync 与全新索引对比覆盖节点、限定名、签名、位置和边。已有宏上下文刷新测试继续适用。本轮没有增加只改宏头便自动重解析所有消费者的能力。

## OceanBase 性能与边变化

在两个隔离副本中，以相同 14,273 个文件初始化，再应用完全相同的 1,000 文件实际内容差异（21,908,222 字节）。使用正常 Rust 扫描器与 8 个解析 worker，串行执行基线 init、修复 init、修复 sync、基线 sync，最后各执行无变化 sync。环境为 Windows、Node v24.11.1、Ryzen 9 7945HX、约 32 GB 内存。

| 操作 | 基线（秒） | 修复（秒） | 变化 |
|---|---:|---:|---:|
| init | 402.154 | 395.515 | -1.65% |
| 1,000 文件 sync | 242.049 | 235.839 | -2.57% |
| 无变化 sync | 0.646 | 0.650 | +0.004 秒 |

这是准确性改善伴随小幅耗时下降，不能认定为显著、稳定的性能优化。每阶段使用新 Node 进程，未清除系统缓存，仅做一轮成对测量；耗时包含索引打开／创建、操作、统计和关闭，不含源码镜像准备和写入变更。

两版均完整结束，失败文件与 pending 引用为 0。实际修改均为 1,000 个文件，基线／修复另分别重索引 86／85 个旧边无法重连的关联文件。失败引用重试从 156,980 条降为 95,811 条，该步骤的执行耗时从 26.543 秒降为 21.917 秒。文件解析与写回变化很小，主要引用工作量仍在。

初始图边数从 5,395,775 增为 5,594,639，其中 references 从 1,442,295 增为 1,642,639。限定名修正让部分原来未命中的成员引用得到目标，例如 `oceanbase::common::ObCellWriter::write_int` 引用真实字段 `pos_`。因此节点数下降不等于边数必然下降。

计时结束后，对同步后的两份相同源码图抽查了跨 12 个文件的新增引用边。其中 11 个样本能对应到真实成员字段；另发现 `ObObj &obj` 参数被误连到单测文件中被错误索引为函数的同名 `obj`。不能将新增边全部算作正确率收益。

中性对照进一步确认：`int Box::read(Item const& obj) const { return obj.method(); }` 加上其他文件中的全局 `obj`，基线和修复版都会产生到全局变量的错误 references 边。这说明参数遮蔽与同名全局符号的解析问题在基线中已存在；本轮限定名改善后，真实项目中的具体误连集合也会变化。该公共问题需作为后续 resolver 修复处理，本轮未修改引用解析器。

性能和边抽查证据位于 `release/benchmarks/oceanbase-declarator-perf-20260927/` 的 `REPORT.md`、`comparison.json`、`reference-edge-samples.json`、`parameter-control.json` 及原始日志。MAME 本轮做了全量提取差异，没有做端到端 init/sync 性能对照。
