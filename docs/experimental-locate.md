# 实验性需求源码定位

`codegraph locate` 根据中文或英文需求／issue，提前查询并读取模型后续可能需要的源码，减少模型自行 grep/read 的次数。它通过已有 codegraph 数据库寻找定义和一跳图关系，在预算内返回核验过的当前代码片段；agent 可以直接分析这些代码，再按需补查其他范围。不调用 LLM、不要求 API 密钥、不执行文档中的代码。

## 使用

此实验性命令当前需要 Node.js 22.5–24 的原生 SQLite，只读打开数据库，不触发同步或索引构建。请先完成初始化；首次构建大仓库索引的时间不计入定位查询预算。

```powershell
codegraph init D:\c_proj\mame

codegraph locate --file .\docs\examples\locate\mame-snapshot-feedback.md --path D:\c_proj\mame
codegraph locate --text '需要改进 video_manager::save_snapshot 的失败反馈' --path D:\c_proj\mame
```

CLI 可直接使用，无需环境变量开关，并显示在顶层帮助中。功能仍处于实验阶段，此版本仅提供 CLI，暂不接入 MCP。

在已建立索引的项目目录中，可以直接运行：

```powershell
codegraph locate --file issue.md
codegraph locate --file issue.md --json
codegraph locate --file issue.md --json > locate-result.json
codegraph locate --text '需要改进 video_manager::save_snapshot 的失败反馈'
```

默认向标准输出写入 Markdown 源码上下文；`--json` 直接向标准输出写入结构化 JSON，`candidates[].source` 包含带行号的源码片段。需要保存时使用重定向。省略 `--path` 时，从当前工作目录向上寻找最近的已初始化项目；`--file` 的相对路径始终相对当前工作目录，不随 `--path` 改变。

## 参数和预算

| 参数 | 默认值 | 约束 |
| --- | --- | --- |
| `--file` / `--text` | 无 | 必须且只能提供一个；UTF-8 文档最多 128 KiB |
| `--path` | 当前项目 | 必须已有索引 |
| `--limit` | 10 | 最多 1–20 条源码候选，最多 5 个文件，每文件最多 4 条 |
| `--timeout-ms` | 45000 | 1–60000 毫秒；覆盖工作线程启动、数据库查询和源码核验 |
| `--max-tokens` | 20000 | 512–32000，整个输出的 token 上限 |
| `--max-tokens-per-clue` | 2000 | 128–8000，且不超过总上限 |
| `--json` | 关闭 | 输出结构化 JSON；默认直接输出按文件组织的源码上下文 |
| `--verbose` | 关闭 | 文本末尾增加排序分数、证据等级和检索统计；同样受总预算限制 |

token 使用随包安装的本地 `o200k_base` tokenizer 精确计数，不联网加载词表。不同模型的 tokenizer 计数可能不同。总上限覆盖实际输出文本，包括 JSON 字段名、转义、Markdown 标记、诊断、预算元数据和结尾换行，不只是源码。`candidates[].tokens` 是该候选 JSON 与独立阅读条目两种表示中较大的 token 数，包含位置、证据、文档原文、关联、源码及展示范围。按文件合并后内容可能共享，因此不一定等于它在完整响应中的边际 token 数。

单条预算不足时优先精简图证据、重复签名和文档引用，然后按整行缩短源码。总预算不足时优先省略冗余摘要、过多的输入线索和低排名条目，尽量保留前排条目的完整信息；不会截断 JSON 或 Markdown 代码块。`truncated`、`partial`、`stopReasons` 和 `budget.omitted*` 明确记录省略。所有保留的输入线索记录同样满足单条 token 上限。文本和 JSON 分别按各自最终输出检查总预算，文本不会先被 JSON 的总预算裁剪。

## 默认源码上下文

默认文本首先提供实际源码，再补充必要的关系和未覆盖范围，不调用 LLM 生成业务解释：

1. **已预取源码**：按文件给出相关符号、定义范围和带行号的源码。合并重叠行；不连续区间插入缺口标记。短定义优先完整提供，长定义保留相关窗口。
2. **相关调用与关系**：只展示选中符号之间的结构化索引关系，保留方向和调用位置；重复关系合并，启发式关系标注为推断，不宣称是完整运行路径。
3. **核验提示和其他查询结果**：例如草案使用返回值与 `void` 签名不一致、明确范围外符号、索引未命中名称。已提供代码中可见的原文命中不重复罗列。
4. **未覆盖范围**：准确列出每个局部定义尚未提供的行区间，供 agent 按需补查。没有源码的条目明确标为仅位置线索，不计入已预取源码统计。文本不展示常规检索上限提示、token 用量和上限，内部仍严格执行预算，JSON 保留停止原因和预算统计。超时、取消、索引不完整及源码核验异常仍显示。建议使用codegraph进一步按需查询，已知符号和文件用 `codegraph_node`（`symbol`、`file`、`includeCode: true`）；尚未定位的符号用 `codegraph_search`（`query` 仅填符号名，`includeCode: "if_unique"`）。

默认不展开需求原文、逐条匹配理由或 `score`、`confidence`、`role` 等内部字段，让输出预算主要用于源码。需要诊断时加 `--verbose`，在源码后追加完整匹配依据、文档引用和统计；程序消费时加 `--json`。JSON 保留原有结构和完整证据。

检索最多提取 64 个去重锚点，每个符号最多查询 64 个定义，候选池最多 200 个节点。只从最多 12 个种子做一跳扩展，每方向最多 20 条边，总共最多 400 条边。最多读取 24 个文件，每文件最多 2 MiB。同步 SQLite 查询在独立工作线程中执行，截止时可以终止线程并返回最近一次部分结果，不会留下查询子进程。token 编码和最后的格式化在返回前执行，耗时另加于工作线程预算；一分钟是端到端性能目标而非硬实时保证。

## 证据与限制

- Markdown 中的行内代码、限定符号、文件路径、代码块调用和错误字符串是线索；中文用于规则化识别文档结构与明确范围提示，不做语义翻译。
- `prose` / `code` / `draft` / `pseudocode` 只是来源标签。普通代码块先待核验，匹配到当前源码后才成为片段证据。代码块中的字符串不会再被当作函数调用解析。
- 明确的“不修改”等表述用于保守排除；复杂否定、跨段指代和未标注的设计意图不保证识别。未出现于正文的对象成员和局部字段不发起独立搜索。
- 精确匹配处理完整限定名；裸名有多个实现时降低权重。同一标识符重复出现不会重复加分。单个弱图邻居不能独立成为结果。
- `verified` 表示定义位置与当前文件内容通过核验；`source_match` 表示在已经读取的文件中发现原文，不等于已确认符号定义。`index_match` 仅确认索引命中；`index_miss` 不证明源码不存在；`out_of_scope` 表示根据文档明确范围提示排除。
- 文件 SHA-256 与索引不一致、文件不可读或超出项目根目录时，不返回该文件的已验证候选。请先 `codegraph sync` 再重试。
- 只复用已经读取的源码检查字符串和未建模的宏／枚举名称，不做全仓源码回退。没有符号或路径锚点、只有业务描述／错误字符串时，可能返回空结果。
- 置信度是定位证据等级，不是缺陷概率或修改正确率。候选是建议阅读的位置，并不声称都需要修改。
