# 根外共享源码软链接

默认保持原有安全策略：仓库内源码正常读取；指向仓库外的软链接不允许读取。
若工程主动使用根外共享源码，可在启动 CodeGraph 时指定可信源码目录：

```bash
export CODEGRAPH_ALLOWED_SOURCE_ROOTS="$(realpath /work/shared-source)"
codegraph init
codegraph sync
codegraph serve --mcp --path /work/project
```

- 多个目录：Linux/macOS 用 `:` 分隔，Windows 用 `;` 分隔。
- 填写现有目录的绝对真实路径，不接受相对路径或软链接别名。不要授权整个用户目录或磁盘；系统根和部分敏感目录会被拒绝。
- 工程必须已有指向该目录的软链接。本选项不添加扫描目录，不允许直接通过 `../` 或根外绝对路径读取文件，也不改变 ignore/language 规则。
- 每次读取仍检查最终真实目标。可信目录内再次链接到未授权目录的文件仍被拒绝；目录名前缀相同不算授权。
- 索引、手动同步和源码查询必须使用相同配置。MCP 客户端应将变量写入服务端进程的环境；共享服务/daemon 应停止后带此变量重新启动，已有常驻进程不会接收 shell 后续的环境变更。
- 外链目标内的修改不能依赖现有 watcher 自动感知，请显式执行 `codegraph sync`。本次修复不更改 watcher、原有 stdio/共享服务模式或数据库归属。
- 未授权的根外源码仍不可读取。目录或忽略文件因权限错误无法完整扫描时，本次扫描失败并中止同步，不把缺失的扫描结果当作源码删除；修复权限后可重试。

该设置允许 CodeGraph 对指定目录中的源码进行索引和返回源码内容，应只填写有权读取且愿意向当前客户端提供的源码目录。

## Git 仓库中的目录软链接

启用上述授权后，扫描器会补充展开 Git 可见的目录软链接。Git 本身只列出链接，不列出链接目录中的源码；CodeGraph 会按工程内的逻辑路径应用忽略规则，再补扫授权目标。跟踪和未跟踪的链接均支持，不会主动扫描未被工程链接引用的授权目录。嵌套链接仍需通过同一真实路径授权校验。

- Linux/macOS 未配置授权变量时，普通 Git 快速路径不变。Windows 的 Git 可能自行展开 junction，因此会额外检查候选路径的链接祖先，防止绕过授权与目录忽略规则。
- 配置非空时，按父目录缓存目录条目以识别链接，不再对每个 Git 文件单独执行 lstat。补扫仅增加显式授权的根外目标，不因开启配置额外展开仓库内目录链接。大仓、网络盘或大量链接仍可能增加扫描开销。
- 补扫应用全局 Git excludes、仓库 info/exclude 与各层 .gitignore，并保留 .codegraphignore 的显式覆盖。普通目录中的否定规则按层级生效；被排除的父目录不会因子层否定规则而自动进入。
- 不跟随软链接形式的忽略文件，策略指纹也不读取这种控制文件；链接损坏或自指循环不会触发忽略 Git 结果的全量回退。授权补扫按物理文件/目录身份去重。
- 同时使用 `.codegraphignore` 反向包含规则时，保留文件系统遍历路线，不使用只补充指定普通目录的混合扫描捷径。配置外部授权时直接使用有授权边界的 JS 扫描，避免不具备该边界的原生遍历提前读取外链控制文件。
- 当前自适应重建不接受软链接源码。遇到这种情况，普通同步降级为增量更新；完整发布校验仍拒绝该输入，不会为了启用外链而放宽原子切换条件。
- Windows 的敏感用户目录（例如 `.ssh`、`.aws`）按不区分大小写规则拒绝，不能通过改写 `.SSH` 绕过。
