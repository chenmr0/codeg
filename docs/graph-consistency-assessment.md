# 图一致性修复：范围、基线对照与阶段性提交

日期：2026-09-07。提交前基线：`93b3a92`。

## 决定

保留并提交已经验证的漏提、增量重连和限定作用域修复；不把“完善整个 C++ 类型推断”作为这批性能优化及正确性修复的前置条件。剩余局部对象/代理调用、枚举别名与逻辑符号归一问题另立范围。

这是阶段性提交，不是“所有图一致性问题已经解决”或正式发布的无风险证明。此前因为整轮图摘要尚未完全还原而建议继续阻塞整批提交；本次补做旧提交对照后，调整这一建议：必须阻止新增回归，但不能把已有解析局限、声明/定义的物理节点切换全部算成新增错误。

## 改动量

本批生产 TypeScript 涉及 14 个文件，新增约 538 行、删除 83 行，包括诊断/名称查询性能工作，并非全是图一致性逻辑。测试涉及 14 个文件，新增约 844 行、删除 24 行；另有约 3.43 MB 的固定 C++ WASM 语法及许可、构建/说明文件。

这不是几行小补丁，但也没有重写图引擎、数据库 schema 或整个解析器。核心边界是：

- 入站边按语义身份重连，未匹配的带原始引用标记的边保留恢复机会。
- C/C++ include 只匹配文件，旧错误 include 有一次性事务修复。
- C++ 继承、成员、明确调用限定名使用更严格的目标证据。
- 更换固定 C++ 语法；对损坏包装及宏恢复仅做有界重解析。
- 名称查询的确定性排序和增量预热策略、耗时诊断。

若继续全面处理局部变量、返回类型、代理对象/operator->、别名、模板及重载身份，会跨越提取、作用域/类型推断、解析候选与查询归一多个层次；不宜再堆叠少数名称特判，具体工作量应独立设计后估算。

## 本次新增的版本归因实验

通过 `git archive 93b3a92` 导出干净源码，在独立目录编译，与当前候选分别运行相同的 9 组最小场景。每组包含初次索引、删除/修改、关闭并重新打开、恢复源码、空同步；没有使用工作区修改覆盖旧源码，也没有操作 OceanBase 原索引。

| 场景 | `93b3a92` | 当前候选 | 判断 |
|---|---|---|---|
| 局部 `PictureData data; data.flatten()`，删除并恢复提供方 | 错连 `OtherData::flatten`，恢复后仍错 | 相同 | 已有局部接收者推断局限，可单独处理 |
| 明确 `PictureData*` 参数调用，同样删除/恢复 | 错连其他类，恢复后仍错 | 缺失时保持未解析，恢复后正确 | 当前修复有效 |
| `Target::Make()`，删除/恢复 Target | 错连 `Other::Make`，还有重复裸引用 | 不错连，恢复正确，无重复裸引用 | 当前修复有效 |
| `using Flags = TargetFlags; Flags::kNone` | 错连其他枚举成员 | 相同 | 已有别名解析局限，可单独处理 |
| 同名 class 前置声明目标删除/恢复 | 从一个声明节点切到另一个，恢复后不切回 | 同样存在 | 物理节点漂移既有；不能仅据此判为调用了不同符号 |
| 同一方法声明/定义目标删除/恢复 | 会切换节点，恢复后不切回 | 同样存在，但初始候选可不同 | 逻辑符号归一另行设计，不能声称当前物理边完全不变 |

本机实验脚本与逐阶段原始结果保留在 `release/graph-scope-assessment-20260907/`（不属于发布包）。这些是代表性形状的版本归因，不是对先前 800 文件差异逐条做过旧版本 A/B 的声明。

## 验证与风险

已有最终专项回归：1,172 通过、0 失败、4 个原有条件跳过；构建、安装包冒烟及原生产物检查通过。OceanBase 中间候选引入过 12 条继承字段漏边，不能把它们说成旧问题；最终补丁后真实文件定向核验 12/12 恢复，并有最小回归测试。

风险为中等、可做阶段性合入，但不是零风险：

- C++ 语法替换和匹配收紧影响正常解析路径；专项覆盖降低风险，不能证明所有 C++ 写法等价。
- 最终三处补丁之后还没有重跑完整 800 文件混合变更/恢复循环。首次发布前仍建议隔离验收该场景，但不再要求把所有旧类型推断缺陷一起修完。
- 800 文件新增实测由前一候选的约 119 秒到修复中间候选的约 150 秒；这些不是干净 HEAD/当前的重复性能 A/B。更保守的匹配可能增加未解析引用和历史重试量，不能声称零性能影响；应单独复测解析/重试阶段。
- 同名声明/定义的节点切换可能影响节点级查询，不能直接视为等价；需结合签名、作用域及声明/定义配对，单独定义逻辑符号查询契约。

数据库 schema 仍为 8、提取版本为 22。旧库能继续使用；首次 sync 会修复指定的旧 include 数据，但空 sync 不会重提所有历史漏提/误提。需要全库获得新提取结果时用 `codegraph index -f`，不必删除数据库或重新配置 init。

提交与正式发布分开：本次只保存已验证的实现和已知边界，不自动发布 npm 包、不改动用户原数据库，也不继续扩大剩余类型推断的修复范围。
