# 项目术语映射

Explore 可以在原有词法检索、自动词段召回之外，加入维护者配置的业务术语候选。
这是查询提示，不是符号覆盖保证，也不是翻译或向量检索。

## 配置

在项目的 `.codegraph-wx/term-mappings.json` 中写入：

```json
{
  "rules": [
    {
      "terms": ["信道配置", "信道参数", "无线信道设置"],
      "symbols": ["getChannel", "getRadioCfg"]
    },
    {
      "terms": ["自动选信道", "自动信道选择"],
      "symbols": ["getAutoChannel"]
    }
  ]
}
```

使用 `CODEGRAPH_DIR` 或历史 `.codegraph` 数据目录的项目，在实际数据目录顶层保存此文件；不要放进 generations 子目录。
该文件无需登记到索引配置，修改后下一次 Explore 自动读取，无需 sync、init 或重启 MCP 服务。

- 查询包含 `terms` 中任一短语即启用该规则；同义词复用同一组符号。
- 术语忽略大小写，将连续空白归一化；英文词需要标识符边界，中文短语可出现在连续中文句子中。
- 符号匹配 `name` 或 `qualified_name` 的完整值，**区分大小写**，不做前缀、子串或模糊匹配。可用实际索引中的限定名减少同名歧义。
- 所有命中规则合并去重，按配置顺序最多使用 16 个不同符号。每个名字最多引入 3 个候选（按文件、行号和 ID 排序），合计最多 24 个候选，后续仍受 Explore 原有预算限制。
- 映射候选按弱种子分数参与正常排序，不作为原文明确点名的强制返回项，也不替换自动词段召回。只指定裸名字时多个同名定义/声明可能竞争；这不是固定绑定。
- 原有 MCP 参数和顶层公共 `findRelevantContext` API 未增加新参数。本功能通过当前原生 Explore 适配层加载，CLI Explore 和 MCP Explore 共用。

配置缺失时行为与未配置相同。坏 JSON、不可读文件、失效符号不会使普通 Explore 失败，也不向普通开发者输出维护告警；独立坏规则跳过，其他有效规则仍可使用。
文件仅支持普通 JSON，不执行脚本、SQL、网络访问，也不支持符号链接文件。

资源限制：文件最大 256 KiB，最多 1,000 条规则，每条最多 20 个术语、32 个符号，每项最多 256 字符；配置内容按文件状态缓存，缓存最多保留 32 个项目。限制是防止配置意外拖慢查询，不是建议填满。

## 维护者检查

```bash
codegraph mappings check
codegraph mappings check --path /path/to/project
codegraph mappings check --json
codegraph mappings check --check-source
```

默认只读当前索引，检查 JSON、重复项和符号的精确匹配，不自动初始化、同步、修复或扫描整个源码仓。符号去重后查索引，候选总数不被展示上限截断；同名候选最多展示 20 条位置。

- `FOUND`：当前索引找到一个候选。
- `MULTIPLE`：多个候选，需要维护者检查；重载、声明与定义也可能有多条记录，不必然错误。
- `NOT_FOUND_IN_INDEX`：当前可靠索引没有找到。**不等于接口已删除**，提取器也可能遗漏。
- `UNVERIFIED`：缺少可用索引，或者索引状态、提取版本、工作树等不足以确认缺失。

默认明确标注 `Source: not_checked`。`--check-source` 额外调用现有变更检测，可能随仓库大小增加耗时；发现源码变化时建议维护者先同步再确认。提取版本过旧与源码变更是不同状态。

退出码：全部找到为 0（多候选仅提醒）；可靠索引存在未命中符号为 1；配置错误、索引不可用/不完整/版本过旧或源码检查未同步等检查不充分情况为 2。`--json` 返回相同的结构化报告，适合维护者自行接入 CI。

## 生命周期

正常 init、sync、重建不会把词典纳入提取语义指纹，修改词典不触发全量重建。
原生离线 uninit 的目录清理会保留 `term-mappings.json`（包括坏配置），删除索引数据后目录可能仍存在；重新初始化时可继续使用。现有 portable storage 的活跃进程删除保护不变，仍须先停止相关进程。
不要手工删除整个数据目录来清索引，否则词典仍会丢失。团队共用的词典应另行纳入备份或版本管理。

## 本轮验证范围

Linux / Node 24.22.1 上构建通过，17 个相关测试文件共 176 项通过，包括真实 MCP Explore、构建产物 CLI、自动词段与映射合并、英文多词单种子、C 函数指针字段与宏、大小写/限定名、读库字节不变、配置编辑后无变更 sync、索引清理后配置保留，以及既有 C++ 检索/输出预算/宏恢复策略回归。没有运行全仓所有测试，也未做 Windows 实机验证。

补充一个受控小型查询冒烟：101 个 C++ 文件、5,103 个节点，同一非空查询，两轮正反顺序，每种配置 60 个热查询样本；未配置、1,000 条规则未命中、命中 2 个符号时 p50 分别约 14.93 / 14.26 / 13.44 ms，p95 约 24.17 / 23.41 / 26.79 ms。保留了命中组 86.29 ms 的慢样本。这些是小型合成索引上的上下文召回调用，不是完整 MCP 端到端或大型业务仓性能保证，也不能据此宣称映射会加速查询。
