# 追加函数的增量存储与引用保留

本优化基于 main-ch-new。提取版本保持 25，不改变数据库 schema，也不要求为这项存储优化单独重建索引。旧版本索引继续使用完整处理路径。

## 适用范围

第一版针对完整文件扫描确认的 C/C++ 增量同步：文件末尾追加独立函数，原始源码前缀的哈希一致，已有符号的持久化属性及坐标不变。继续按文件解析；存储时保留稳定符号的行，只更新文件节点并插入新增函数。

只保留有原始引用记录的、未限定名称的精确匹配调用、类型引用及构造引用。当前提取结果必须包含完全相同、唯一的引用位置与所属节点。候选集合的完整指纹必须仍然一致；若同名候选包含字段或方法，则交回正常解析，因为这类匹配还依赖成员作用域和继承关系。可能经过 include 导入解析的名字也不复用。

复杂接收者调用、限定名、失败引用、旧式无来源记录的边、未知框架、监听器局部路径同步，以及不能证明安全的编辑继续使用原路径。因此这不是通用的“所有未改变引用都跳过”，也没有关闭历史失败引用重试。

## 依赖失效

- 新增同名函数或重载会重新解析对应精确引用，包括源码没有变化的调用文件。
- 宏、include、类型、namespace 或函数体修改等不满足追加边界的变化会使本批已保留引用回退。
- 纯追加有时会暴露现有解析恢复差异。该文件仍完整重建，同时记录其所有候选名称变化；其他文件只在完整候选事实仍一致时复用精确引用。不会仅按名字、节点 ID 或候选数量判定相同。
- 捕获候选指纹之前若该名字已经被本批其他文件修改，不将修改后的数据误作旧结果的依据。
- 实际解析/读取失败、未知状态及未消费的重试日志均保守处理；成员与继承相关引用不走本次引用保留路径。

## 中断与内存

差量文件写入在一个事务内完成。保留关系与恢复标记一起提交，整个 sync 成功后才原子确认；中断后先把已保留关系还原为待解析引用，再继续普通同步。失效重放按每页 1,000 条读取和提交，途中再次中断也能继续。

只保存有界的候选指纹和本批文件/名称集合，不保存项目级源码、AST 或全部引用数组。每个名字最多读取 2,001 个候选（超过 2,000 则不复用），最多保留 10,000 个名字的指纹，单文件候选关系读取上限为 50,001 条（超过 50,000 则回退）。

可通过 `CODEGRAPH_NO_APPEND_DELTA=1` 关闭新增优化；已有中断标记仍会恢复，避免关闭开关后遗留旧关系。详细模式新增 `append-delta` 记录保留节点、实际写入节点、保留引用及重新入队引用的数量；普通 `store-detail` 仍统计原完整存储路径。

## 验证与边界

新增回归覆盖旧节点/边行保留、UTF-8 前缀、无末尾换行、新重载及未修改调用者、宏/include/namespace/函数体变化回退、候选属性变化、同名成员、旧关系重建、事务回滚、跨页引用、中断后依赖变化和 WASM 差量 SQL。

每类正常编辑使用完整重建作为节点、边及失败引用对照；真实项目测试使用相同初始数据库和相同 1,000 个源码追加。原始记录与最终结果位于工作区 `artifacts/sync-append-delta/`。

WASM 的完整 API sync 在未修改的 f37bd5c 上已经存在维护后 `Statement closed` 问题，本次没有改动 SQLite 适配器；新增差量事务及 SQL 在 WASM 后端单独验证。这不能表述为 WASM 完整 sync 已修复。

## OceanBase 重复对照（2026-09-28）

同一提取版本 25 初始库、同一 1,000 文件尾部追加、同一构建开关对照，共六个独立进程，顺序为关闭/开启/开启/关闭/开启/关闭。Windows x64、Node 24.11.1、8 个解析 Worker，所有轮次使用相同 WASM 运行参数；本轮启用全部语言，共 14,347 个文件。

| 指标 | 关闭优化 | 开启优化 |
| --- | ---: | ---: |
| 三轮 sync 耗时/秒 | 190.98 / 188.76 / 192.32 | 155.70 / 193.64 / 158.48 |
| 中位数/秒 | 190.98 | 158.48 |
| 变更引用解析数 | 748,906 | 527,390 |
| 历史失败引用尝试数 | 48,263 | 48,263 |

中位数降低约 17.0%，一次开启组运行明显偏慢，已保留该样本；不能保证每轮或 Linux 项目获得相同收益。991 个文件命中，保留 41,598 个节点和 221,516 条引用；9 个文件按原流程处理。历史失败重试仍为 0 条新增成功，本项没有解决这部分成本。

六轮节点、边、文件及未解析引用全表规范化哈希一致，排除时间戳及边/引用的数据库自增 ID；pending 与增量恢复标记均清零。测试源码的 1,000 个字节哈希已逐一验证恢复。相关回归共 360 项通过、1 项因缺少原生宏扫描组件而条件跳过；新增用例 22 项全部通过。未做本轮完整 init 性能对照。
