# C/C++ 符号声明证据修复与差集核验

2026-09-27，基线 33aac39，提取版本 25 → 26。本轮没有接入预处理器，没有修改真实 OceanBase/MAME 源码或原有索引。

## 修复范围

1. typedef 仅从声明符字段提取别名，不再把被引用类型的 type_identifier 当成另一个声明。遍历多个 declarator，解开指针、数组和函数指针；struct/union/enum 标签保留为相应类型节点，既有内联类型的主节点和字段归属保持兼容。C++ 内联 union 与 C 使用一致的类型体提取路径。
2. 对 `Type object(Enum::VALUE)`，仅在当前文件已提取到该限定枚举值时，将语法树中的函数声明解释为对象初始化。保留声明的 const 属性；识别绝对限定和外围命名空间，遇到更近的同名类型/命名空间停止向外猜测。未知限定名继续作为潜在参数类型处理，不扫描外部数据库猜测。
3. 损坏的长声明或多声明符恢复时，函数名读取当前声明符，而不是整个父节点中第一个 function_declarator。位置与签名仍取对应声明符；已知宏在损坏长声明中的裸调用或 return 表达式，不能借用父节点开头的返回类型进入函数索引。

根因：typedef 补提在 f65578c 中将直接 type_identifier 当成别名，并将 tag 当作 type_alias；函数名字读取整个父节点的路径出现在 3b7b885；初始化问题来自 Tree-sitter 不知道限定标识符是类型还是枚举值，而提取器直接把含 function_declarator 的声明当作函数。历史提交用于定位代码来源，本轮未重跑全部历史引擎。

修复未使用项目路径、业务符号名或宏名黑名单。尚未将跨文件未知枚举、using 导入、宏残片、损坏 AST 的所有局部归属、函数指针全局变量等歧义一并解决。

## 验证方式

回归覆盖多别名、指针/数组/函数别名、标签类型和字段保留，多函数声明及条件编译下的名字/位置一致性，普通与限定参数类型、const 对象初始化、作用域遮蔽；另有正反向 sync 与 fresh init 的节点及边一致性比较。

OceanBase 14,273 文件、MAME 21,810 文件使用此前冻结 manifest 和相同宏上下文全量回放，只统计提取结果，不把回放耗时当作 init/sync 性能。本轮多个检查并行执行，不作性能收益结论。

提取版本升级只标记旧图内容过期；需要完整重建才能刷新未修改文件的旧节点。普通增量 sync 不会自动修复全部存量记录。

最终构建通过，相关专项及通用 C/C++ 子集共 529 个不同测试用例通过。最终专项批次中一个自动校验子进程用例在并行语料回放时超过 5 秒，单独重试 2.33 秒通过；未修改超时阈值。没有执行全部语言的全套测试。

OceanBase 828 个期望别名全部存在，101 个真实标签保留为类型。9 个直接初始化对象恢复为 constant（包含最初发现的 2 个样本）；cover.c 的 4 个错位函数恢复各自名字。节点总量变化包含删错、重命名和补回，不是净删错数。

## 差集核验口径

固定上一轮 CodeGraph v25 对 CBM v0.11.0 的差集样本：11 类，每类按节点 ID 的 SHA-256 排序取 12 条，共 132 条。对源声明、位置、原始语法树祖先和必要的宏定义进行检查，再追踪修复后对应记录。

- 正确符号：名称、类别、源位置和归属有证据。源码各条件分支均可索引；不声称在某次构建配置中全部启用。宏的命名空间前缀按 CodeGraph 的展示归组理解，不当作 C 预处理器作用域。
- 真实但类型或归属错误：源声明存在，但 kind/owner/名称位置对应有误。
- 伪符号：该位置并未声明这一符号。例如 typedef 引用已有类型时额外制造一次别名声明。
- 待确认：宏完整展开、归属或条件编译证据不足；没有因为 CBM 缺失就判错。

修复前样本为 87 正确、8 元数据错误、2 伪符号、35 待确认。这是分层诊断样本，不是全库准确率估计。两库同名同行匹配也不是真值；不能把未匹配节点全部标成错误。

对同一批源位置追踪修复后记录：2 个伪别名消失，3 条类型/名称错误已纠正，其余样本继续保留。存续或替换的 130 条记录按修复后的类别统计如下；样本不能外推总体，0 伪符号也不意味着全库无伪符号。
