# 默认语言范围与完整模式验证

基于 `c06ed32` 实施，工作分支为 `perf/init-throughput`。本文记录提交前的实施与验证情况；后续阶段性提交保留已知问题记录，尚未写入 `main-ch-new` 工作区。

## 行为

- 默认仅索引 `c`、`cpp`、`objc`、`python`、`lua`；`.m` 和 `.mm` 均沿用 `objc` 标签。
- 仅 `CODEGRAPH_ALL_LANGUAGES=1` 启用完整模式，恢复全部已有语言及特殊格式。保留所有 grammar 资产和低层解析能力。
- 文件扫描、Git/hybrid/native 路径、直接索引、scoped sync 和 watcher 使用同一范围；Worker 的启动、回收和重建显式继承单次操作捕获的范围。
- 框架检测和纯语言关系合成跳过禁用范围，保留通用 field/emitter 回调以及 C/C++ 关系。render 合成从名称索引查找候选类，保留原边字段和顺序，不再枚举全部类及其成员。
- 范围变更触发一次强制提取与文件集合核对，保证同内容的保留文件也刷新框架节点，同时移除退出范围、已删除或已忽略的文件。旧的无范围标记索引视为完整模式。
- 迁移中断时保留 pending 标记，即使环境切回原值也会重新完成迁移。宏恢复降级与语言范围分开处理，避免恢复告警导致每次 sync 全量重建。
- 未变更范围的普通 sync 保留原增量路径；仅打开查询不迁移。环境变量仍是运行配置，数据库标记不会覆盖进程环境；MCP 和已有守护进程须使用一致配置并重启生效。

## 正确性与同步验证

- `npm run build` 通过，`git diff --check` 通过。
- 20 个相关测试文件共 343 项不同用例通过（主体 342 项，后增加宏降级迁移用例并重跑其 14 项相关测试）。
- 额外以默认范围运行 C/C++ sync 图一致性、跨文件恢复、宏扫描和关系合成：4 个文件、37 项通过。
- 覆盖默认/完整双向迁移、旧库迁移、空图、直接索引边界、scoped sync、取消/异常恢复、两种 Worker 配置传播、watcher 配置变化，以及节点/边/失败引用完整业务字段比较。
- render 对照覆盖 Python 自定义 `this`、C++/ObjC/Lua、JS/Java/Vue/Svelte、重复 render、多父 contains 和每类上限，完整边字段及顺序与旧实现一致；2,000 个无 render 类不会触发全类扫描或 contains 查询。无统计新库及真实 MAME 的查询计划均为名称索引 → 边索引 → 类主键。
- 完整语言框架测试中 3 项 Windows 清理错误已在未修改的主分支构建复现，原因是测试漏关数据库；补齐测试清理后通过，未改动 JVM 生产解析逻辑。

结果文件：`tests-all.json`、`tests-default.json`、`tests-recovery.json`，均在 `bench-logs/language-scope-20260911/`。

## 既有识别边界

`.inc` 仍映射 PHP，默认排除：MAME 部分 `.inc` 实际为 C++ 片段，OceanBase 部分是 SQL；本次不将它们一律重分类为 C++。`.luau` 与 `.lua` 不同，前者需要完整模式。完整模式同样遵循已有 ignore 规则，不表示解析所有任意扩展名的文件。
