# Git 授权源码软链接补扫与安全回归

## 范围

基线为 `39faa470500513879423f720b1673c4551ecb87f`。修复 Git 仓库未展开已授权目录软链接、Windows 敏感用户目录大小写绕过。没有修改共享服务项目身份、术语映射检查或索引清理规则。

## 先复现，再修复

真实隔离 Git 仓库内有 `local.c` 和指向外部共享目录的 `linked`，配置 `CODEGRAPH_ALLOWED_SOURCE_ROOTS`：

- 非 Git 目录扫描 2 个文件并命中外部函数。
- Git 未跟踪和已跟踪链接都只扫描 1 个文件；`indexAll()` 返回 `complete: true`、无错误，却没有外部函数。
- 普通目录先建库，再执行 `git init` 和 `git add`，源码不变；基线 `sync` 返回 `filesRemoved=1`、`coverageVerified=true`，外部函数被移除。
- Windows 平台大小写逻辑中 `.SSH` 等名称没有命中原有敏感目录拒绝条件。

## 修复

1. 仅配置了外部源码授权时，检查 Git 可见候选中的目录链接，应用逻辑路径忽略规则和真实目标授权校验，再补扫链接树。不会主动扫描所有授权目录。
2. 补扫复用既有遍历器，保留嵌套忽略、目录循环防护和文件去重；嵌套链接不能借此逃逸到未授权目录。
3. 普通仓库未配置变量时保持 Git 快速路径不变。有外链授权且使用反向包含规则时，保留完整遍历路线，避免混合扫描遗漏链接。
4. Windows 敏感用户目录改用已有平台感知的路径包含比较，拒绝大小写变体和其后代。
5. 新增文件发现后，发现自适应完整规划原本拒绝软链接。对此仅将普通规划降级为增量同步；完整发布校验仍拒绝，不放宽原子发布安全条件。

## 验证

- 先写回归，在基线观察失败，再实施修复。
- 构建通过，`git diff --check` 通过。
- 10 个定向测试文件：210 项通过、3 项跳过。
- 新增 12 项覆盖真实 Git 跟踪/未跟踪链接、初始化 Git 后不误删、外链增改删、未授权目录、嵌套逃逸、忽略规则、循环、目录名带源码扩展名、混合扫描、原生不可用回退、普通规划降级及完整发布拒绝。
- Windows 敏感目录测试使用平台逻辑模拟，不是 Windows 实机测试。当前未连接 Windows 环境。
- Rust 协议与回退测试通过；没有宣称真实原生扫描二进制直接支持外链。

## 小规模串行性能

OceanBase `5e8a63d29dae9fde5e962b8fcc7b167d438fc343` 的 `src/sql/engine/basic` 递归 120 文件。三组均为真实 Git 仓库，各自新建索引、统一预热后逐轮交替顺序，严格串行测试无变更和 3 文件变更，各 5 轮。计量整个 CLI 进程 wall time，中位数如下：

| 场景 | 基线普通目录 | 修复普通目录 | 修复授权外链 |
|---|---:|---:|---:|
| 无变更 sync | 0.364 秒 | 0.363 秒 | 0.376 秒 |
| 3 文件变更 sync | 1.156 秒 | 1.143 秒 | 1.113 秒 |

30 次正式 sync 全部成功；无变更均 modified=0/removed=0；变更均 modified=3/removed=0。最终三组源码哈希一致，均为 120 files / 8,501 nodes / 24,945 edges，数据库完整性检查为 ok。

本组未观察到普通路径显著退化，数十毫秒差异不能解释为优化收益。基线 Git 外链本来无法正确建立索引，不将其失败/漏数据耗时当作性能对照。

## 限制

- 配置非空时对 Git 可见候选增加文件类型检查，并遍历相关外链树；大仓、网络盘、大量授权根的成本需要另测。本报告不是全量 OceanBase 性能验收。
- 含软链接的完整重建规划降级增量，不承诺其自动原子重建。完整发布校验仍严格拒绝软链接。
- watcher 不增加外链监听，目标变化仍需手动 sync。
- 保留既有 realpath/read 竞态模型，不声称消除并发恶意替换。
