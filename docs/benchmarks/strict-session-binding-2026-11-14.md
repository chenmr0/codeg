# 严格共享会话隔离修复

基线：`f156dbcee6831d5f57a64e2876fb8c7ed2661faf`。本轮只修复严格会话路径重新解析及严格握手超时降级，不包含 Windows 服务端点身份或扫描器修复。

## 问题与修复

### 校验路径与查库路径不一致

真实临时 A/B 项目分别建立 C 源码索引，B/back 软链接指向 A/src。原会话按真实路径判断 back 属于 A，却把原始 B/back 交给工具；后者沿原始目录找到 B 的索引。基线返回 B 独有的 `betaMarker` 及 `example.c:1`。

修复后，严格会话接受合法别名，但初始化和所有工具调用（包括省略 projectPath）均明确传入服务绑定根，不把调用者的原始路径继续交给下游重新选库。工具层通过内部绑定直接打开或复用该根的图实例，禁止向上查库。会话创建时记录真实项目目录的 dev/ino 身份；目录被替换或文件系统不能提供可靠身份时拒绝严格请求。索引代际切换不改变项目根身份。普通客户端仍可跨项目，严格客户端直接指定 B 仍被拒绝。

复核又发现会话期间移走内层索引可触发上层索引回退，已补“尚未打开索引”“已打开索引”“项目根替换”三个真实索引回归，均不再返回外层项目正文。目录身份检查不宣称抵御恶意并发文件系统操作造成的所有 TOCTOU。

### 严格客户端 hello 超时降级

生产 daemon 等待 client hello 3 秒后兼容旧普通客户端。生产严格代理在读取 daemon hello 后延迟 4.1 秒再发送严格标记，基线仍转发 MCP，ping 成功，说明已经降级到普通会话。

修复新增受限会话确认：daemon 安装严格会话后返回确认，严格代理确认前不转发任何 MCP 输入。缺失、错误策略、格式错误、超长确认、连接关闭及超时均断开失败，不回退普通模式。普通旧客户端的可选 hello 行为不变。升级后应重启 daemon；旧 daemon 未实现确认时严格连接会拒绝，不静默退化。

## 验证

- 新增路径别名和延迟 hello 回归在基线真实失败。
- 干净构建后，10 个定向套件 57/57 通过。
- 路径测试使用真实文件系统软链接与两个实际小 C 索引，生产 daemon/session/engine，通过 TCP 字节流作隔离测试载体。
- 握手测试启动真实严格代理子进程，MCP 输入预先写入 stdin；延迟 4.1 秒时确认失败且没有 MCP 响应，正常连接可 ping，确认本身不会泄漏到 MCP stdout。
- Windows 分支测试为平台逻辑模拟，不是 Windows 实机。
- 当前 Linux 环境 Unix socket listen 返回 EPERM，提权执行最小探针仍相同，因此本轮没有真实 Unix socket/Windows named pipe 端到端验收。TCP 仅为测试载体，不是产品新增网络模式。
- 额外 Explore 取消与交付语义套件 3/3 通过；普通 mcp-daemon CLI 全套尝试受运行环境阻碍未完成，已中止，不能算通过。
