## 热点证据

使用上一阶段保留的提取完成快照 `fork-fixed-extraction-quiet/codegraph.db`：23,380 文件、1,614,524 节点、1,650,802 提取边、7,851,814 待解析引用。每次复制到新目录，重现 fresh init 的数据库模式，以相同 6 个解析 worker 重放引用解析及关系合成，避免重新提取源码。

基线重放的最后一个引用批次结束时，主线程累计计时如下。`pool.resolveBatch` 是等待 worker 的墙钟，其他项为主线程调用耗时；本轮尚未重叠这些阶段。

| 环节 | 时间 |
| --- | ---: |
| 等待 worker 计算并返回 | 514.369 秒 |
| 读取下一批引用 | 16.199 秒 |
| 构造边对象 | 5.738 秒 |
| 写入边 | 39.750 秒 |
| 删除已解析引用 | 17.715 秒 |
| 标记失败引用 | 3.421 秒 |

最慢区间主要是 m68000 生成文件。选取 rowid 4,000,000 之后的 20,000 条真实引用，全部来自 `src/devices/cpu/m68000/m68008-sdf8.cpp`，用 Node CPU profiler 单线程重放。采样显示 `inferCppReceiverType` 占约 71.9%（含内部调用）；其中 `getFileLines` 占总采样约 32.7%，大量其余时间耗在重复声明正则匹配，GC 占约 7.9%。这些包含关系的百分比不能相加。

源码原因有两层：

- 大文件的完整 `string[]` 拆行结果超过既有 16 MiB 文本缓存预算，每次类型推断又重新拆分、估算后丢弃。
- 同一接收者在大量调用位置出现，每条引用都从调用行向文件开头扫描，重复执行相同的源码正则；成员声明不在当前文件时，这些扫描往往遍历很长的前缀。

## 实现与语义边界

新增 `CppReceiverDeclarationCache`，默认只处理至少 128 Ki 字符的源码。用 `Uint32Array` 保存行起点，按需切出一行；对每个接收者建立有序的原始声明证据，按调用行号二分定位，再倒序检查声明。

保持以下行为：

- 与原 `split(/\r?\n/)` 相同的行内容，包括 CRLF、孤立 CR 和末尾空行；声明正则、每行第一个匹配及名称边界不变。
- 当前文件从调用位置向文件开头查找；候选头文件的顺序和头文件内从头到尾的检查顺序保持原样。
- 不缓存最终类型、目标节点或置信度。遇到 `auto` 时仍使用当前图的函数返回类型推断；失败后继续检查更早的声明。
- 以实际源码字符串为键，同一路径的新内容不会复用旧证据；`clearCaches()` 同时释放本缓存。
- 默认保留预算 32 MiB、至多 16 份源码、每份至多 64 个接收者条目；字节超限时淘汰或不保留计算结果。小文件、超预算输入及没有新增接口的外部 context 使用原扫描路径，文件不会被跳过。
- 沿用 `CODEGRAPH_NO_RESOLVE_TEXT_CACHE=1` 回退开关。预算是估算的缓存保留量，不是全进程 RSS 上限。

热点样本初版从 16.369 秒降至 1.333 秒，解析成功数均为 19,235，完整结果 SHA-256 均为 `f2b8d795294fe61516f893e1070d33a0538b40bf529e6b50b0093a06bb2b5310`。这是局部 CPU 样本，不能外推为整个 init 的降幅。

**完整 init 从 19 分 10.5 秒降至 14 分 44.6 秒，节省 4 分 26 秒，缩短 23.1%。** 引用解析及索引切换缩短 47.2%；总时间包含提取和合成阶段的实际波动，没有将局部降幅外推为整体收益。新增缓存并非内存优化，本轮全程 RSS 峰值增加约 0.49 GiB。

本轮 157 次 CPU 采样的外部平均占用 1.68 核，P95 为 2.29 核、最大为 2.72 核，无超过 4 核的采样窗口。CPU 数字为采样窗口平均值；同步步骤可能延后采样，不能排除更短的瞬时峰值。上述完整对照和重放均为本机单次运行，尚未做多轮交错重复。

完整 init 成功处理 23,380 个文件，文件错误 0，`complete=true`。与第二阶段逐项比较：节点和文件业务字段完全一致，全部边无新增、删除或修改，未解析引用多重集相同，pending=0、外键检查为空、`quick_check=ok`。节点、文件及未解析引用顺序指纹也与上表重放指纹相同。

当前完整运行中，提取及写入约 397 秒，已超过引用解析及索引切换的 322 秒。后续应先剖析提取阶段的宏恢复源码构造，以及优化后仍耗时的引用匹配区间；社区的清理重叠可以再单独评估，仍需保持边提交和继承关系可见性的顺序。

构建通过。相关 6 个测试文件、191 项测试全部通过，新增 8 项回归涵盖原扫描等价性、源码/头文件顺序、动态图下的 auto 推断、源码替换、容量淘汰及缓存释放。
