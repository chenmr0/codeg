# 发布期间新增源码软链接的安全恢复

## 问题与复现

基线：`f156dbce`。真实 portable 发布子进程完成准入后，在开始解析时新增已授权源码目录链接。候选库会被发布，但后续全内容校验抛出 `Symlink source is not eligible`；待校验标记仍在，`sync({adaptive:false})` 也不能完成。

新增测试先在基线运行：两个恢复场景失败，普通 fullHash 拒绝链接的控制场景通过。

## 修改

- 候选数据库验证完成后、切换前，在现有验证 worker 内重新检查源码资格。新出现的源码链接使候选验证失败，portable 父进程保留旧库并回退增量同步；不增加额外 worker 启动。
- 发布和恢复采用不同语义。普通发布规划和普通 `fullHash` 仍拒绝源码链接。
- 已有待校验标记的数据库，允许专门的恢复扫描读取经过公共授权检查的链接目标。每个文件仍完整计算内容哈希，不使用大小/mtime 快捷判断。
- 恢复读取前后检查真实目标、授权及文件属性，链接在本次读取期间改指向时中止，不将该轮视作完整验证。
- 只有一轮完整且无变更的验证通过后才清除待校验标记。没有标记的数据库不能借恢复标志绕过发布资格。

## 验证

新增 `publication-symlink-recovery.test.ts`：

1. 实际发布子进程解析期间新增链接：原数据库身份不变，增量回退完成，外链函数可查询。
2. 实际发布完成后主动中断，在带待校验标记的库上新增链接：下一次 `adaptive:false` 完成恢复，标记清除，外链函数可查询。
3. 普通 fullHash 发布资格依然拒绝链接。
4. 恢复读取期间将链接改指向未授权目录：验证失败。
5. 没有待校验标记时，worker 拒绝通过恢复标志放行链接。
6. 链接目标内容发生等长修改、mtime 恢复原值：恢复扫描仍通过完整内容哈希发现修改。

同时运行 adaptive plan、read worker、真实子进程同步、数据库发布验证、小变更同步和宏漂移恢复套件。测试使用已重新构建的 dist。新增回归最终 6/6 通过；发布校验与真实子进程同步套件另外 24/24 通过。构建通过，`git diff --check` 通过。

## 限制

- 实测环境为 Linux，Windows 原生验收未执行。
- 文件系统变化不受数据库 writer lease 锁定。发布前检查缩小风险窗口，不承诺原子冻结源码；检查后的新增链接由带标记的完整恢复覆盖。
- 新增一次发布前源码目录/属性资格检查，只发生在全量重建发布路径，不增加普通增量 sync 的扫描。大仓耗时未单独测量。
- 扫描遗漏、ignore 文件授权及 Windows 路径身份另有配套修复。本补丁不将不完整扫描视为安全，依赖扫描器正确传播覆盖错误。
- 普通源码读前 realpath 与实际读取之间的对抗性并发竞态未改造为句柄级沙箱，不宣称全面消除 TOCTOU。
