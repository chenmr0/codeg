# 第五阶段：名称缓存与方法候选评分

日期：2026-09-10。基线提交 `dde73cd`。本阶段针对 OceanBase 引用解析剖析中确认的名称拆词缓存淘汰和候选评分计算开销。

## 实现

原有 `getNameWords` 保留大小写及其 8,192 项 / 4 MiB 缓存。新增可选的 `getLowerNameWords`，专用于不区分大小写的评分，使用独立的 65,536 项 / 32 MiB 有界缓存。它先按原规则拆词，再逐词调用 `toLowerCase()`，保留单词顺序和重复项。

这种分离使现有接口的返回值保持不变，也避免在每次候选比较时重复做小写转换。没有实现新接口的外部 context 继续使用原有分词接口或普通拆词函数，随后进行相同的小写转换。

`matchMethodCall` 的方法名回退评分同时做以下调整：

- 先统计符合方法名、节点类型和语言条件的候选数量，避免每条引用创建两份筛选数组。
- 按原始候选顺序评分，用循环和词成员判断替代临时 `filter` 数组及嵌套回调。
- 重复的接收者单词仍分别计分；候选单词重复不会重复贡献。同语言的加分、跨语言回退和接受阈值不变。
- 最大可能分数为接收者单词数加语言加分。如果最大分数不足接受阈值，直接返回未匹配；遇到第一个达到最大分数的候选即结束扫描，同分时仍选原顺序中的第一个。

没有缓存最终目标或匹配分数，候选内容、语言或顺序变化会在下一次调用中重新判断。两个词缓存分别计费，`clearCaches()` 释放全部派生文本缓存；沿用 `CODEGRAPH_NO_RESOLVE_TEXT_CACHE=1` 开关。

新增缓存每个 resolver 最多保留约 32 MiB 的估算数据，按需增长；6 个 worker 的新增估算预算合计最多约 192 MiB，主线程也有自己的 resolver。这不是全进程 RSS 的硬上限。文件拆行缓存和 C++ 接收者声明缓存保持不变。
