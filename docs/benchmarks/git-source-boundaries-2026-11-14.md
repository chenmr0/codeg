# Git 外链补扫边界修复验证

基线：`f156dbcee6831d5f57a64e2876fb8c7ed2661faf`。本次仅处理扫描与控制文件边界，不包含共享会话、Windows Unicode 身份和发布恢复的其他修复。

## 修复

- 不读取源码树内软链接形式的 `.gitignore` 等忽略文件；全局 Git excludes 保留用户配置软链接的读取行为；策略指纹仅读取普通文件，并验证其真实目标属于工程或授权目录。不存在与无法读取不再混为一谈。
- 补扫引入 Git 全局 excludes、仓库 info/exclude、根与嵌套 `.gitignore`。嵌套否定按层级生效，`.codegraphignore` 仍为显式覆盖。不会穿越已排除的父目录。
- 仅补充授权的根外目录链接，不因启用授权额外展开根内链接。对 Git 已展开的 junction 后代，先检查链接祖先，再交给受限遍历；循环、别名与硬链接按物理身份去重。
- 局部损坏、自指链接不会让整个扫描放弃 Git 候选并改成全量遍历。无法读取目录或忽略文件则抛出覆盖错误，本次同步中止，保留原索引；没有把部分名单标记为完整。
- 使用按父目录缓存的目录条目识别链接，代替逐 Git 文件 `lstat`。Windows 即使未配置授权也检查候选祖先，因为 Git for Windows 可能已展开 junction。
- 外部授权启用时直接走 JS 授权边界，避免旧原生扫描器提前读取外链控制文件。未声明 Rust 原生直接支持这些外链语义。

## 真实复现与回归

新增 10 项测试：软链忽略文件、全局排除及 ELOOP、全局配置软链接兼容、根内链接、嵌套否定、真实 EACCES 目录与忽略文件、Git 展开后代、CodeGraph 覆盖优先级、物理文件去重。

真实 Linux EACCES 测试使用独立低权限子进程：先建立索引，然后改变目录或忽略文件权限，再执行 `sync({adaptive:false})`。同步抛出扫描覆盖错误，原 `remote_fn` 仍可查询。

在精确基线构建后跑初版 7 项可运行用例：6 失败、1 通过。修复后最初新增 9/9 通过，构建及 9 套定向回归共 **160/160 通过**。随后追加全局配置软链接兼容用例，重新构建及该套 **10/10 通过**。

额外扩展 `language-scope` 和 `sync-diagnostics` 两套有 11 项失败、29 通过；在精确基线重跑结果相同（旧接口及诊断预期问题），没有将其计入通过。

## 扫描阶段成本

本地 Linux 文件系统，12,000 个 Git 可见候选、120 个 C 文件、没有目录链接。预热后逐轮交替、严格串行各 5 次，只测扫描函数，不含启动或完整 init/sync：

| 配置 | 中位数 |
| --- | ---: |
| 基线不配置授权 | 84.31 ms |
| 基线配置有效授权 | 165.23 ms |
| 修复配置有效授权 | 110.20 ms |

相比基线开启授权减少约 33.3%；仍比基线未开启授权多约 30.7%。这不是全仓或网络文件系统性能结论，也不是 init/sync 提速承诺。

## 验证边界

- 本机没有 Windows 实机。Windows Git 展开候选使用生产分离函数的受控输入验证，不能代替真实 Git for Windows/NTFS/junction 验收。
- 软链接形式文件的 Windows 回归若缺少创建权限，明确跳过，不计通过。
- 文件系统验证到读取之间仍存在原有并发替换窗口，不宣称实现完整防 TOCTOU。
- 发布前新增链接和待校验恢复由独立修复处理，本次不放宽完整发布验证。
