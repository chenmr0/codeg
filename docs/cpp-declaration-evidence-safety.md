# C/C++ 声明证据与条件分支安全

在 main-ch-new 分别移入 33aac39f、eda57d7b 后，保留其声明符、类型别名和限定名改进，并修复两个可复现的静默错误。

## 宏同名不能证明当前文件中的函数是宏调用

全项目宏预扫描会收集互不包含的文件中的宏。不能因为函数名与宏同名、返回类型名与空宏同名，就删除一个有明确声明符的函数。

空宏前缀排除现在要求：当前文件 AST 确认两个宏名，源文件中存在早于使用位置的空对象宏及函数式宏定义，并且没有 include、条件编译、undef 或多行指令等使判定不确定的边界。字面量不能被去注释/遮罩逻辑当成空替换体。遇到不确定状态保留声明，既有声明宏展开继续独立执行；本实现不是完整 C 预处理器。

最小回归是 api.cpp 中 `typedef int Result; Result api(int x) { return x; }`，与未包含头文件中的 `#define Result`、`#define api(x) ...` 共存。修复后 api 函数及 caller 到真实函数的调用边均保留，init、无变化 sync、修改文件后的 sync 都覆盖。

保守处理可能保留少量歧义宏包装节点，不能声称消除全部伪符号。例如 OceanBase 的两个 GTest 静态互斥量宏包装声明缺乏本文件宏定义证明，保留原解析结果，避免按跨文件名字猜测。这不影响该项目的原始引用提取集合。

## 枚举值证据必须适用于当前条件分支

每个枚举值记录所属条件分支的 AST 身份，仅当枚举所在分支为当前声明分支的前缀时，才可用于将函数形状重分类为对象初始化。`#if`、`#else`、`#elif` 互不混用。头文件保护宏及同分支、嵌套分支内的正常枚举初始化保留。

遇到同一限定名也有类型证据时，不做枚举值推断。`#if 0` 中的枚举不再使有效分支的 `void api(Mode::ON)` 变成变量。未尝试计算预处理条件，也未扩展跨文件枚举推断。

## 与 main-ch-new 现有修复的兼容

typedef 标签改用真实 struct/enum 类型，而不是 type_alias；字段仍由已有主类型节点持有。沿用已有匿名枚举底层类型识别，避免将 `typedef enum : u32 {...} State` 的 u32 补成枚举标签。更新旧测试的真实标签类型预期，保持名称、字段及包含边检查。

保留初始化器宏恢复限制、增量存储与失败引用查询优化。采用 eda57d7b 的提取版本 26，本批未发布的修复不额外升版。main-ch-new 的版本 25 索引需要完整重建才能刷新未修改文件；普通 sync 不会自动修复所有存量错误。若使用过其他分支的旧版本 26 实验包，也需手动完整重建。

## 验证范围

新增 22 项测试覆盖 C/C++ 声明、定义、方法、跨文件宏冲突、undef/条件/include 边界、定义先后、正常声明宏恢复、条件分支枚举及持久化调用关系。另执行包含原有宏恢复、匿名枚举、typedef、增量存储和失败引用的合并回归。

OceanBase 14,143 个、MAME 21,429 个 C/C++ 文件采用冻结源码及同一宏上下文全量对照；节点、边、引用、诊断的逐文件摘要及节点差异均落盘。属于提取正确性验证，不是完整 init 性能测量。最终报告位于测试工作区 `artifacts/cpp-admission-fix-20260929/REPORT.md`。

最终验证合计 1,014 项通过、1 项原生组件条件跳过（合并回归 1,012 项，加随后补充的 2 项 C/C++ API 前缀用例）。全量回放两项目均无提取失败、诊断变化或节点删除。OceanBase 新增 2 个保守保留的宏包装节点；MAME 新增 1,992 个节点，涉及 16 个文件，包含此前误删的 OpenGL、SQLite、zlib API 和少量歧义宏包装节点，不能将新增数量直接视为正确率。

MAME 原始引用计数减少 1,679，集中于 3 个文件。逐项对照后，3,068 条引用保留源位置并改挂到恢复的函数节点；忽略归属差异后没有丢失调用引用，剩余减少项为 references（样本是函数参数及局部名字），符合恢复函数作用域后不再将局部名字当全局符号引用的行为。完整差异保存在 reference-differences.json。此处不等同于对全项目最终解析边逐条认证。
