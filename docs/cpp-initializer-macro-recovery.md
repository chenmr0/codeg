# C/C++ 初始化器宏恢复边界

基于 main-ch-new；与 typedef / 匿名枚举修复同属提取版本 25，不再增加版本号。

## 问题与实现

MAME 的 T11 操作码表使用 `OP(x) &t11_device::x`。项目其他文件的 `illegal` 宏会把 `OP(illegal)` 污染成 `&t11_device::util::stream_format(...)`。旧启发式将这个表达式当作函数声明，重解析操作码表，可能超时并保存 `declaration_macro_recovery_skipped`。该告警会使未修改的文件在后续 sync 中再次尝试恢复。

本次让声明作用域检查获得完整调用区间及展开文本。只在调用完全位于健康、闭合的 `initializer_list` 中，并能确认展开不会逃出初始化器边界时，跳过辅助声明恢复：括号和方括号必须匹配；结构分隔符、预处理指令、原始字符串、拼接、三字符组、双字符组和不确定词法形态均保留原恢复路径。

主 AST 的符号、边和引用提取不变。检查不增加 AST 重解析或持久缓存，也没有扩大宏展开预算。

不能只按初始化器位置过滤。例如 `BRIDGE(name)` 展开为 `0 }; int name; int more[] = { 0` 时会生成真实全局声明；本实现保留此类结构宏，以及正常文件/命名空间/类作用域声明宏。

## 失败恢复与兼容性

未取消失败文件的重试机制。已有失败告警的文件仍会尝试一次实际恢复；修复后的 T11 成功提取并清除告警，后续无变化 sync 才走快速路径。其他仍未成功的恢复继续保留告警和恢复机会。

不改数据库结构、历史失败引用状态、500 条同名历史引用上限及重试日志。全局宏集合的完整 include / undef / 条件可见性问题未在本次重写；此修复解决初始化表达式误入声明恢复这条已确认的超时路径。

## 验证

- 33 个相关测试文件、855 个测试通过；复核补充 `%:` 双字符组保护后，27 个边界/集成用例再次通过。覆盖 C/C++ 结构宏、普通宏、嵌套数组、同一行声明、保留基础节点/边/引用、旧告警恢复、连续无变化 sync、后续真实修改。
- 真实 T11 文件与完整 MAME 宏上下文（76,605 条定义）：旧 main-ch-new 在 65 秒保护上限仍未完成；修复后三轮单文件提取为 128 / 103 / 96 ms，无告警，节点、边和引用与基础解析完全一致。
- 真实 T11 和 Z8 文件的隔离项目：init、旧告警恢复、两个独立重开实例的无变化 sync 均完成；图谱哈希一致，后两轮零文件重提取，源文件未变。

这些是单文件和两文件隔离验证，不是完整 MAME/OceanBase init 或 1,000 文件 sync 的性能保证。原始日志、逐条历史引用重放记录和报告位于工作区 `artifacts/retry-timeout-fix/`。
