# 全量引用解析：保留来源节点索引

## 修复范围

`4849bc1` 为 C++ 继承补查新增 `getPendingSupertypes()`，读取尚未落库或失败的继承引用。该查询依赖 `unresolved_refs(from_node_id)`，但既有全量引用窗口会删除该索引，导致查询按 status 扫描大量 pending/failed 行。

修复仅将 `idx_unresolved_from_node` 从 `BULK_RESOLUTION_REF_INDEX_NAMES` 中移除。代码解析/入库阶段仍延迟该索引，进入引用阶段前照常恢复；其他引用索引仍按原策略延迟。没有改变查询条件、继承语义、批次大小、Worker 数量、缓存限制、WAL 或数据库 schema。

索引生命周期是读取依赖的一部分：一个索引不能仅因主循环按 id 读取，就被判定为写入开销而删除；必须同时检查解析器内部查询及只读 Worker。

## 兼容性与代价

- 使用原 schema 已有索引，不新增表、索引或迁移版本。
- 旧版本中断后缺失该索引的数据库，由现有 open/healBulkParseIndexes 路径恢复。
- 增加引用删除时的索引维护开销，不增加全量 JavaScript 缓存。
- 同一批 5,000 条引用的诊断副本实验：3,940 条删除及 1,060 条失败更新，从约 11ms 增至 21–27ms（事务内，不包含提交和整个批次其他工作）。不能将该数据直接外推为完整 init 的耗时或内存。
