# 固定路径索引 sync 端到端验收

在独立的 Git 工作副本上测试，通过真实的 `codegraph init`、CLI、SDK 和 MCP 入口运行。默认路径是 `.codegraph-wx/codegraph.db`。除“旧库升级”外，初始索引用待测版本建立。不要让两个版本同时写同一份库。

## 观测方法

```bash
codegraph sync -v
tail -n 10 .codegraph-wx/.runtime/adaptive-sync.log
sqlite3 -readonly .codegraph-wx/codegraph.db \
  "SELECT value FROM project_metadata WHERE key='portable:database-id-v1';"
```

记录每次 sync 前后的 ID、退出码和本次新增日志。相同的非空 ID 表示仍使用原库；两个不同的非空 ID 表示已经换库。单条 `strategy: rebuild` 只表示选择了重建。重建成功还须检查：固定路径相同、新符号能查到、已删符号消失、`codegraph status --json` 显示完整，以及空闲后正常回收本次操作的 `old.db` 和 `candidate.db`。协调锁文件、活动库的 WAL/SHM 可以存在。

## 建议执行顺序

| 场景 | 操作 | 预期 |
|---|---|---|
| 健康空同步 | 完成初始化及一次预热后，连续执行两次 `sync -v` | `incremental / no-content-changes`；ID 不变，增删改均为 0；整库只盘点一次，无候选库、无内容哈希读取、无写库 checkpoint |
| 小改 | 在有至少 160 个等规模源文件的仓库中，分别修改 1 个和 10 个文件的函数；另测少量新增、重命名和 Git 未暂存删除 | `incremental`；同一 ID；新增和删除可查询验证，小改仅检查疑似变化文件的内容 |
| 大批量 touch | 同时更新至少 128 个源文件的 mtime，保持内容不动。之后再 sync 一次 | 首次校验内容，文件改动数为 0，可写回 stat；复用本次盘点，不创建新库；第二次健康空同步可只读完成 |
| 文件阈值边界 | 512 个大小相同的 C 文件，每个一个独有函数。分别从同一初始库修改 127 个和 128 个文件，替换为**不短于原内容**的新函数；确保大小或 mtime 真正变化 | 127 个走增量；128 个达到 25% 文件和字节覆盖率，`rebuild / structural-large-change`，ID 改变 |
| 纯新增和纯删除 | 从 128 个等规模文件新增 128 个；另从 256 个等规模文件删除 128 个，均保留非空目标 | 新增靠文件与目标字节覆盖，删除靠文件与旧节点覆盖；都可在没有耗时样本时重建 |
| 节点阈值 | 用一组较大的 C 文件生成超过 10,000 个函数，其余文件只含少量函数。查 `files.node_count` 确认即将修改的文件少于 128 个，但拥有至少 10,000 个且至少占 25% 的旧节点。只改这一组 | 走节点规则重建；对照组低于节点数或占比，并且不满足文件规则时走增量 |
| 原来的 `0\|18` 现场 | 使用 `ba2a147d` 初始化 160 个等规模源文件，在**隔离副本**关闭所有 writer 后删除 `project_metadata` 中的 `adaptive:source-owner-v1`；核实标记不存在、18 个 `adaptive_owner_*` 触发器仍在。换用待测版本，先改 1 个，再改 144 个 | 第一次增量，第二次直接按规模重建；无需手工 init 或恢复标记。原有或缺失的 `adaptive:cost-history-v1` 均不应改变结果 |
| CodeAgent / MCP 与 CLI 混用 | 初始化分支 A，切到大改分支 B 后启动 MCP 触发 catch-up；再在终端 sync。另测已运行 watcher 时切分支，以及后续单文件保存 | 最终索引反映 B，已有查询连接切到新库；后续小改仍增量。同步期间取消 MCP 后再次执行 CLI，能继续更新；用 ID 判定是否实际换库 |
| 并发、失败和恢复 | 大改触发重建时，用已打开的读者查询旧符号。在构建中改源码或切分支，另测取消和发布后追平中断，再运行普通 sync | 构建期旧库可查。成功切库后 ID 改变，sync 完成时查询结果与当前源码及解析配置一致。中断追平后重跑应补齐差异并保留已发布的 ID。可用 `PRAGMA quick_check` 和 `PRAGMA foreign_key_check` 核对新库 |
| 配置及目录覆盖 | 修改 ignore 规则，核对真实增删；修改解析配置，核对需要重提取的文件。用项目内 `CODEGRAPH_DIR=.codegraph-alt` 重复大改 | 策略按实际索引工作量选择，增量不得漏处理；目录覆盖下也能换库。已有 `CURRENT` 代际格式单独跑兼容测试 |

## 性能验收

额外边界：删光所有受支持源码时，预期仍在原库上增量清理。若提取版本升级或解析配置改变，即使文件字节相同，也要按需要重新提取的文件计算规模。

以 `1765271f` 为对照。相同源码快照、同一完整起始库的两个独立副本、相同 Node/文件系统/扫描后端。双方各预热一次，关闭 watcher 和其他跑分，每轮交替 AB/BA；在双方处理完当前一轮后再写入下一组同样的修改。不要把只有一方实际处理了变更的结果作对照。

在 OceanBase 和用户的 Linux 5G 工程分别测空同步、单个 C++ 文件实改、10 个文件实改，每个场景每版本至少 7 次独立 CLI 进程。记录 `time codegraph sync -v` 的墙钟时间、增删改计数、扫描模式和逐次结果；用中位数验收：**新版 ≤ 老版 + max(100 ms, 老版 × 5%)**。Git/hybrid 和原生扫描路径分别对比，至少使用一次实际用户工程的默认配置。大改另测包括建库、验证、发布和补同步在内的总时间，并在同一目标源码上用独立 init 验证结果。
