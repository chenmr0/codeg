# C/C++ 通用符号提取修复

2026-09-26 至 2026-09-27。实现基于干净的 `bfe0a38`，提取版本升级到 **24**。

## 修复范围与原因

之前的三方审计已在 OceanBase、MAME 和中性语法样例中复现以下问题。本次规则依赖声明结构、宏定义及源码作用域，没有项目路径、宏名或变量名黑名单。

| 问题 | 引入来源 | 修复 |
|---|---|---|
| 类内宏调用被当成方法，部分还被当成字段 | `97b8362` 扩大类内声明入口 | 统一检查宏调用证据；保留带返回类型的同名函数、构造函数、对象式字段宏和真实展开符号 |
| include 语句片段里的赋值被当成全局变量 | `ba38bde` 的赋值补救过宽 | 必须存在相邻的损坏类型声明和普通 `=`，才允许补救 |
| 宏在同一行生成类和函数头，后续函数体被截断 | `93d2913` 的稀疏重放 | 扫描整行的多段声明和完整闭合边界；隔离独立函数体语句干扰，保留空语句、展开行及类内声明证据 |
| 条件表达式、构造初始化列表中的限定调用变成方法 | `3b7b885` 的文本补救 | 要求返回类型前缀合法，且位于可执行体与预处理指令之外 |
| 损坏 AST 让局部变量逃逸 | `7e4aae1`、`18722eda` 等声明恢复路径，部分问题原版已有 | 独立扫描注释、字符串、指令、条件分支及平衡作用域；只用可确认的闭合区间排除局部变量 |
| 类外静态成员定义丢失类名 | `9715e685` 只保留声明符叶节点 | 保留完整限定名，正确合并当前命名空间；不删除真实静态成员 |

另处理两个关联问题：声明宏没有源代码分号时，不把宏名作为字段；语句宏替换产生的分号不能被借用为变量声明终止符。损坏声明中的直接类/结构体定义也会被保留。

全量差异复核进一步覆盖了超过 512 行的函数、多行原始字符串、被误吞入宏参数列表的后续类，以及被误吞入函数体的显式模板实例化。辅助解析只隔离可以确认的独立函数体语句，保留宏展开行和类内代码，避免连带删除宏生成的真实类型。

如果完整展开行明确包含命名类型定义，但辅助 AST 没有产出该类型，才触发一次更小的独立解析。该解析保留原始命名空间，只补回缺失类型及其包含的符号，并连接到原有命名空间节点；不导入其他函数或变量解释。宏自行提供起始括号的独立函数，在辅助声明输入中闭合，避免不确定的结束宏吞并后续类型。

完整的匿名命名空间展开则单独解析，同时保留其类外静态成员定义、显式实例化和注册对象；从原来的辅助输入中移走这些行，避免重复解析同一批展开。独立解析要求括号闭合且以声明终止符结束，仍以函数头结尾的展开继续保留后续源代码函数体。

兼容性复核还发现声明宏展开器的两个通用词法问题：定义中的 `//` 原先在整个外层展开结束后才清理，会吞掉外层声明的尾部；逐字符扫描也会把 `123suffix` 这样的预处理数字后缀误当成宏名。现在在代入定义前清理其行注释（保留字符串中的 URL），并把预处理数字作为完整 token 处理。宏扫描结果和原生扫描协议不变。

原先声明宏展开最多处理 4,096 次，达到上限后静默停止；前部识别结果变化会使原本能解析的尾部声明跌出额度。现将通用预算提高到 8,192 次，并在超限时产生 `declaration_macro_expansion_limit` 诊断。极大文件仍可能存在未展开的尾部声明，因此这次修复不保证全部宏生成符号都能提取。超过旧上限及达到新上限的中性用例均有覆盖。

宏展开节点的列号映射回原始调用行。同一宏调用行生成同名声明和定义时，按现有 ID 规则合并；后续回归修复改为优先保留定义，不依赖声明与定义的先后顺序。

## sync 与存量功能

同一个 MCP/watch 进程内，修改宏定义后原先会继续复用旧宏上下文。现在新增/修改宏定义文件、删除已有宏定义或删除 C 家族文件会使宏上下文失效。刷新在下一次有 C 家族文件需要解析时进行；普通消费者修改、无变化 sync、仅删除文件的 sync 保留原有扫描快路径。旧文件是否含宏使用索引查询判断，不加载其全部符号。

回归测试验证：宏签名和静态成员名变更，正反两个方向的 sync 与重新初始化得到相同节点、限定名、签名、位置和边；也覆盖删除最后一个宏、删除宏文件及无变化同步。编译后的 worker 路径另行验证通过。

该变更不引入宏依赖文件的自动全量重解析。仅修改宏头而没有重新解析其消费者时，仍需按现有机制更新相关文件，或完整重建。

## 28910d25 的边界回归修复

后续修复将提取版本从 26 升至 **27**，补齐三个会影响持久化符号的边界：

- 作用域分类先跳过配平的 `alignas(...)`、`[[...]]`、`__attribute__(...)` 和 `__declspec(...)`，避免属性中的括号阻断基类冒号识别。带 `decltype` 基类的对齐类型可以恢复宏成员，真实函数体仍排除局部声明。
- 与宏同名的构造函数使用最近的 class、struct 或 union 判断所属类型，保留 union 构造函数的声明和内联定义，包括嵌套 union。
- 宏恢复节点先区分所属类型、完整参数声明符及成员限定符，再对同一符号优先保留定义。声明在前或在后均不改变定义身份；不同重载不会因处在同一宏调用行而相互覆盖。

回归覆盖源码提取、作用域分类，以及修改文件后 sync 与全新索引的节点和边一致性。旧版本 26 索引需要完整重建才能修正未重新解析的文件。

### 真实回放后的宏身份与静态属性补修

上述初版随后经过 OceanBase、MAME 回放，发现选择类外定义会丢失类内声明的 `static` 信息，也确认同一宏调用行的不同重载及不同类型成员存在 ID 冲突。当前补修仍属于尚未发布的提取版本 27。

辅助解析在生成节点和包含边之前就区分符号身份。所属类型、模板特化、完整参数声明符、成员 `const`/引用限定符及函数模板参数进入身份键；参数名、默认实参、值参数的顶层 cv 不作为重载差异。身份计算不使用被截断的展示签名。无冲突节点沿用原 ID，有冲突的各项使用确定性 ID，并同步更新包含边及受影响的主解析引用。

只有匹配为同一成员的声明和定义才合并静态等元数据，避免将静态属性传给另一个重载。模板类内声明与类外定义也进行匹配。原文件中已经明确写出的声明则通过展开前后未变化的源码尾部和参数位置对齐，避免辅助解析的命名空间恢复差异重复生成节点。

新增 19 项提取回归及 1 项持久化/sync 回归；包括重载增删和恢复、跨类及跨命名空间同名成员、构造函数与拷贝构造函数、模板、长签名、回调参数及静态属性隔离。构建通过，19 个相关测试文件共 272 项通过。该修复针对声明宏恢复，未统一改写其他语言或普通源码节点的 ID 规则。

最终构建重新提取 OceanBase 14,143 个、MAME 21,429 个冻结 C/C++ 文件，均无新增失败、诊断或静态属性丢失；原始引用按节点身份归一化后无减少。原来出问题的 6 个 OceanBase 文件中，47 个 `eval_vector` 定义均保留静态属性；GoogleTest 的 5 组比较函数均同时保留两个重载。节点净增分别为 8,132 和 1,292，包含原来被 ID 冲突覆盖的符号，不等同于正确率指标。

既有 RPC 宏错误恢复及部分主解析命名空间不完整仍有局限；78 个异常限定名变化已经逐项保留源码位置对照，不计为修复收益。本轮没有执行两个真实项目的完整 init/sync 或最终调用图逐边认证。完整数据和范围说明见本机 `artifacts/macro-identity-final-20260930/REPORT.txt`。旧索引（包括此前版本 27 的实验索引）应完整重建。

## 宏类型后续源码成员恢复（提取版本 28）

可信 MAME 声明位置样本揭示了 `28910d25` 遗留的另一组回归：548 个字段、3 个静态属性以及 3 个 `namespace_` 前缀的方法，在 `d66f7169` 仍未恢复。旧版将前 551 项错误地提取为变量或常量；不能通过关闭局部变量过滤来修复。

辅助声明恢复现在依据有界宏展开区分类型头和函数头，支持宏类头、构造函数宏及源码类型名中的标识符宏。只有完整宏类型作用域中的声明位置可以扩展类型名 token，不对普通字段或健康源码类型进行任意项目宏替换。主解析仍使用原有的局部变量排除规则。

不在宏调用行上的成员必须具有辅助 AST 的直接成员声明证据，并能沿类型包含关系追溯到已恢复的宏类型；函数体、构造初始化项及 ERROR 猜测不作为成员证据。保留原始成员坐标，对已经存在的嵌套类型纠正其包含边，避免同时挂在文件和类型下。`namespace` 误解析检查改为匹配关键字边界，保留合法的 `namespace_push/pop/prefix` 标识符。
