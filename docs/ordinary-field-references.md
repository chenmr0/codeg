# 普通字段引用策略（实验分支）

本分支在 C/C++ 中默认不保存**可由完整声明语法直接证明为普通数据字段**的逐位置 `references` 边。字段节点、原签名、类归属、类型关系以及 `calls` / `defines` / `contains` 保留。

## 范围

- 目前可证明的范围：无语法错误的原生标量声明及其非函数指针、数组、引用形式
- 保留函数指针、函数指针数组、成员函数指针及未知类型的使用证据
- `typedef` / `using` 别名、自定义类、`std::function`、`decltype`、`auto`、`void*` 等未证明为普通数据的类型仍保留
- 不改变全局变量、常量、枚举成员、宏或命名空间引用

这是一项保守策略，**不是删除所有字段引用**，也不能用“字段总边数”推算可减少的数量。

## 开启完整字段引用

运行索引命令的环境变量设为 `CODEGRAPH_FIELD_REFERENCES=1`（`true` 同样生效）。未设置或其他值使用默认策略。应在 CLI、MCP 或 daemon 所在进程中统一设置；已启动的服务需重启以读取环境变化。

索引记录策略。策略切换后的普通 `indexAll()`、`indexFiles()` 或 `sync()` 会自动重建已有索引，一次重建可能接近完整 init 的成本。v36 旧库在提取版本 v37 下亦需重建。中断后保留待重建标记，不能把混合策略库当作已完成。

## 增量更新

省略边的原引用记录停放在现有 `unresolved_refs` 表的 `suppressed_field` 状态，不计入 pending。它们是策略重审证据，不是可查询的图关系。

相关符号的身份/字段类型证据改变时，重审对应名字的记录。普通 no-op、位置移动、仅函数体或注释变化不复活全部记录。字段暂时删除后保留原引用证据，以便重新出现或改为可调用字段时恢复。源文件被删除/重提取时，沿用原引用记录清理流程。

## 成本与验收边界

后置过滤仍执行名称解析，而且保留重审记录。因此边减少不等于同比提速、内存下降或数据库缩小；需通过同负载实测给出收益。当前仅为实现说明，不能代替尚未完成的回归、真实旧库升级、发行包及性能验收。
